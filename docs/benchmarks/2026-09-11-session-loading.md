# 首次打开对话：索引与恢复路径优化

日期：2026-09-11。平台：macOS 14.8.7，Intel i7-9750H 2.60GHz，16 GiB RAM；Rust 1.97.0，Node 24.15.0。代码为当前工作区未提交改动。

## 实现

1. 前端复用已取得的 Session cwd；后端按 ID 读取权威元数据，不为授权扫描其他会话。索引不参与实际操作授权。
2. 每个 Session 保存可丢弃的 metadata.json。正常追加事件后原子更新；读取时用日志长度、修改时间和 Session ID 检查缓存。缺失、损坏或日志变化时重新恢复生成；正文仍是唯一权威。索引写入失败不改变日志提交结果。
3. session/new、session/load 不等待扩展初始化；session/prompt 仍先完成扩展就绪。历史恢复与完整投递水位屏障保留。
4. Host 控制锁按 Session 隔离，列表无需等待历史重放的控制锁。列表及目标恢复的磁盘读取进入 blocking pool。记录控制锁等待、授权、打开、历史投递、响应、列表索引和扩展准备耗时；前端记录请求、投递等待和同步投影耗时。同步投影时间不代表 DOM 可见时间。

## 本轮：首页窗口与自动补齐

保持 ACP session/load，在命名空间 _meta 的 keencode/history 中传入 limit、cursor。limit=-1 为全部，正整数 1..100 按完整根轮次计数；不传扩展仍执行完整加载。桌面首页请求最近 2 轮，首页投递完成后即可显示，随后每批 10 轮自动补齐旧历史，每批前让出绘制机会。

Journal 在权威恢复时建立根轮次、provider 和上下文稀疏索引，分页利用已有记录字节偏移 seek。后续 cursor 读取不重开 Runtime、不重置实时投递；旧页独立归约后前插，保留实时水位和当前状态，并校验失效 cursor。前端取消过时任务、保护跨页子代理状态，并补偿前插后的阅读位置。
