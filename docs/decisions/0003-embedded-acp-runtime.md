# ADR-0003：采用进程内 ACP 运行时

- 状态：已采用
- 日期：2026-08-01

## 决策

KeenCode 的 Agent 核心供应商化保存在仓库中，由 Tauri 后端通过进程内传输运行 ACP。前端只消费 ACP 请求、响应和通知，不建立第二套会话协议或模型厂商适配层。

当前唯一边界如下：

1. Session、消息、重放、Goal、Todo 和子 Agent 状态以 ACP 为权威数据源。
2. Tauri 负责本地项目、文件系统、终端、Git、密钥、窗口和运行时生命周期。
3. 模型请求和流式响应转换由内置 Agent 核心处理。
4. 多 Session 可并行运行；界面焦点只决定当前展示，不改变命令所属 Session。
5. Goal 按项目持久化，Todo 按 Session 投影，子 Agent 限制为单层。
6. 工具直接执行，不存在权限模式、信任记录或逐次确认状态。
7. Skills 来自 KeenCode 用户目录、当前项目目录和已启用插件；MCP 读取 KeenCode 应用配置目录中的唯一配置。
8. 供应商源码与 KeenCode 修改记录保存在 `vendor/` 中；许可证和来源见根目录第三方声明。

## 不包含的能力

首版不包含多 Agent DAG 编排、外部消息渠道、遥测服务、本地 Embedding、Ambient Memory 或未进入当前产品范围的文档处理模块。未进入首版范围的模块不编译进运行时，也不保留关闭状态的入口。

## 数据与配置原则

公开发布前只接受当前唯一 schema。未知字段、旧枚举、旧目录、旧命令和旧配置直接报错；不执行迁移、别名映射、历史路径探测或静默回退。标准模型协议的必要容错和操作系统差异不属于应用 schema 兼容层。

## 验证

每次更新供应商源码后必须验证桌面后端、Agent 核心、ACP 会话与工具中间件测试，并检查发布二进制依赖图中不包含首版非目标模块。
