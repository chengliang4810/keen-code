# 0005：本地记忆流水线

## 状态

已采用。

## 目标

KeenCode 默认根据此电脑上的历史根会话生成本地记忆，并在后续会话中按需注入。聊天记录、记忆状态和生成文件均保存在当前唯一的 `~/.keencode` 数据根目录。

## 决策

- 使用两阶段流水线：逐会话提取，再做全局整合。
- 只扫描已空闲 12 小时、90 天内、至少包含一轮问答的根会话；每次最多提取 8 个，避免启动时持续占用模型和 CPU。
- 第一阶段将结构化候选、任务状态、退避时间和使用统计原子写入 `~/.keencode/memories/state.json`。
- 第二阶段按使用次数与最近使用时间选择最多 200 个候选，生成 `raw_memories.md`、`rollout_summaries/`、`MEMORY.md` 和 `memory_summary.md`。
- 每轮只把受限长度的 `memory_summary.md` 作为隐藏开发者上下文交给 Peri；用户正文与持久对话历史保持原样。
- 提取和整合复用当前用户选择的模型供应商；未配置供应商时后台任务静默跳过。
- 关闭开关只停止生成和使用，不删除文件；删除动作清空记忆目录内容但保留聊天数据库。
- 记忆根目录若是符号链接则拒绝清空，避免删除链接目标。

## 取舍

- 候选状态使用一个小型 JSON 文件，不新增第二个 SQLite 依赖和连接池；单进程内通过流水线原子门串行执行。
- 不引入本地 Embedding 或向量数据库。短摘要常驻，详细记忆通过 `MEMORY.md` 和会话摘要按需搜索。
- “本地”描述存储与控制边界，不承诺模型推理离线；使用远程供应商时，筛选后的会话内容会发送给该供应商完成提取。

## 验证边界

- 单元测试覆盖设置契约、模型 JSON 解析、秘密行脱敏和可移植文件名。
- 前端测试覆盖设置项渲染；生产构建验证类型与资源打包。
- Peri 全量库测试验证每轮隐藏开发者上下文没有破坏现有会话执行契约。
- 真实供应商提取质量、12 小时空闲调度和桌面视觉效果仍需在安装后的原生应用中验证。
