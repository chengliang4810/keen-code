# ADR-0002：确定首版范围、性能基线与暂缓能力

- 状态：已采用
- 日期：2026-07-28

## 背景

KeenCode 以当前工作台源码作为界面基线，并以进程内 ACP 作为唯一 Agent 会话契约。本文只定义当前首版范围。

## 决策

1. 单平台实际安装包不得超过 `50 MB`。
2. 内存基线只以软件启动稳定后的空闲占用和一个活跃 AI 会话运行时的占用作为首版验收依据。
3. 多会话并行必须可用并记录增量内存，但暂不作为技术栈否决条件。
4. 首版不实现严格 Plan 模式。
5. 首版保留项目级 Goal 和会话级 Todo；不实现 Swarm 任务图。
6. 首版保留单项目多 Session 并行和单层子 Agent。
7. 首版不编译本地 Embedding、PDF、Bedrock、Memory Sideagent 和 Ambient Memory。
8. 首版保留插件市场、Skills 和 MCP 三个同级扩展管理入口。
9. 首版使用进程内 ACP；不接入外部消息渠道、Topic Channel、共享 KV Context 和递归 Deep Swarm。
10. 模型协议请求和流式响应转换全部由内置 Agent 核心负责，桌面层不重复实现协议适配。
11. KeenCode 首版不建立模型厂商协议适配层，也不建立第二套会话协议。
12. 模型设置只保留自定义供应商，不提供任何模型厂商的官方账户、套餐或额度界面。

## 性能测量场景

首版至少记录以下数据：

1. 安装包文件大小。
2. 安装后应用体积。
3. 冷启动到首个可交互窗口的时间。
4. 启动稳定后的进程 RSS 和 CPU。
5. 单个会话从发送请求到完成期间的峰值 RSS。
6. 第二个和第三个并发会话带来的增量 RSS，仅作记录。

每次结果必须包含操作系统、硬件、构建模式、测量命令和测试步骤。

## 暂缓 Plan 模式

Goal 和 Todo 是任务状态结构，不是强制只读模式。首版工具直接执行，不实现“先计划、用户批准、再执行”的 Session 状态机，也不维护审批状态。

后续若重新设计 Plan 模式，必须形成新的产品决策，不能复用已删除的审批链。
