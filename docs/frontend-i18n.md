# 前端国际化边界

前端 locale 以 ZCode 3.14.3 固定提交
`29628c9acdb81b703bbd4080c207a0e7ce5e276e` 的 `packages/ui/src/i18n/`
结构为来源。目标路径仍以 `packages/ui/src/i18n/` 为准；迁移期间存在的
`apps/ui/src/i18n/` 或根 `src/i18n/` 只能作为临时兼容路径，不新增第三套
目录。

## 规则

- `en-US` 提供稳定键形状，`zh-CN` 提供默认中文显示。新增键必须同时更新
  两个 locale，并保留来源组件需要的插值参数。
- 语言只影响界面展示。会话 ID、RPC 方法、协议枚举、工作流 `type`、文件路径、
  项目名、模型名和用户消息保持原值。
- 组件在渲染时读取 locale；不要在模块初始化、缓存或持久化 Journal 中固化
  翻译结果。切换语言不能通过重建应用根节点来丢失输入草稿和展开状态。
- 日期、数字和相对时间显式传入 locale，不能依赖宿主默认语言；布局必须容忍
  中文和英文长度差异。
- 被裁剪功能的 locale 键、路由入口、菜单项和帮助文案一并删除。仅保留目标
  聊天、工具、历史、设置和工作流定义需要的界面词条。

## 来源与产品差异

保留来源组件的 DOM、className、键盘行为和语义令牌；KeenCode 只在品牌、
目标功能裁剪和 RPC 接线处适配。语言切换本身不是后端会话状态，也不改变
Journal 的权威内容。完整验收以 `docs/frontend-acceptance-matrix.md` 为准，
未执行的语言切换、刷新恢复和原生窗口项目标记为 `pending`。
